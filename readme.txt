== Description ==

Aomark Listings is a configurable listings engine for WordPress. Start from a Real Estate, Directory, or Custom Listing preset, then adjust visitor-facing names, categories, filters, and fields in a guided admin screen.

The plugin creates and manages:

* Dedicated custom post types for each listing type.
* Public category- or tag-style taxonomies.
* Structured WordPress post meta fields.
* Search, filtering, sorting, numbered pagination, and Load More results.
* Connected filter, result, and map views with normal URL fallbacks.
* Listing fields, galleries, metadata groups, and current-listing maps.

Six Elementor widgets are included: Listing Results, Listing Filter, Listing Map, Listing Field, Listing Gallery, and Listing Meta. Listing types and their native WordPress editor remain available without Elementor; Elementor is required only for these visual widgets.

Version 3.0.0 and newer do not depend on Houzez, `fave_*` fields, SSRE shortcodes, or a theme-specific property structure.

For the shortest setup path, see `docs/quick-start.md` in the plugin package.

== Installation ==

1. Upload the plugin folder to `/wp-content/plugins/` or install the release ZIP.
2. Activate Aomark Listings from the Plugins screen.
3. Open Aomark Listings in the WordPress admin menu.
4. Choose a starter listing type and review its friendly names, categories, and fields.
5. Add at least one published listing.
6. In Elementor, add Listing Results and optionally connect Listing Filter and Listing Map with the same Listing Type and Connection ID.

When upgrading from 3.4.x, clear full-page and CDN caches once. Version 3.5.0 signs public AJAX configuration, so cached markup generated by an older release is intentionally rejected while the normal non-JavaScript result page remains available.

== Frequently Asked Questions ==

= Is Elementor required? =

No for listing types and the native listing editor. Elementor is required for the six included frontend widgets.

= Can I change an existing post type, taxonomy slug, field ID, or meta key? =

Existing technical identifiers are read-only because changing them without a data migration can disconnect existing posts, terms, metadata, URLs, and saved Elementor documents. Friendly labels remain editable.

= How do I connect a filter, result grid, and map? =

Choose the same Listing Type. One compatible group connects automatically. On a page with several groups, enter the same unique Connection ID on the Filter, Results, and Map that belong together.

= Can two groups for the same listing type keep separate shareable URLs? =

Their live AJAX behavior is isolated by Connection ID, but the public `alm_*` URL format represents one state per listing type. Use separate pages when two same-type groups must each survive a full reload as independent shareable states.

= Does filtering work without JavaScript? =

Yes. Filter forms, reset, sorting, and numbered pagination use normal URLs. AJAX and Load More progressively enhance that server-rendered behavior.

= Why is a map empty? =

Verify that published listings have a Location field with valid coordinates and that the page can reach the configured tile provider. The results grid remains usable when map tiles are unavailable.

== External services ==

The plugin contains Leaflet JavaScript and CSS locally; it does not download executable code from a CDN. Location features optionally contact the following services when a site owner uses them:

= Photon address search =

The default geocoder is the public Photon service operated by Komoot (`https://photon.komoot.io/api/`). It is contacted only after an authenticated user who can edit posts types at least three address characters in a listing location editor.

The site's server sends the address query, an optional two-letter country restriction, the site URL and plugin version in the User-Agent, and normal server request metadata such as its IP address. The plugin requests at most five results, limits uncached searches per editor, and caches successful results in WordPress for 12 hours. The endpoint can be replaced or self-hosted with the `aomark_listings_geocoder_endpoint` filter.

Service information: [Photon](https://photon.komoot.io/), [Photon source and license](https://github.com/komoot/photon), and [Komoot privacy policy](https://www.komoot.com/privacy).

= OpenStreetMap tiles =

The default map layer is requested from `https://tile.openstreetmap.org/` when an administrator opens a listing location editor or a visitor opens a page containing an Aomark Listing Map. Requests go directly from that person's browser to the tile service. The provider can receive the IP address, browser User-Agent, referrer, and requested tile coordinates as part of a normal web request.

Service information: [OpenStreetMap tile usage policy](https://operations.osmfoundation.org/policies/tiles/), [OpenStreetMap Foundation privacy policy](https://osmfoundation.org/wiki/Privacy_Policy), and [copyright and attribution](https://www.openstreetmap.org/copyright).

Using location widgets or the location editor constitutes configuring these services for the site. Aomark Listings also adds suggested text to WordPress' Privacy Policy Guide so the site owner can describe the actual setup to visitors. The plugin itself sends no analytics or telemetry to Aomark.
